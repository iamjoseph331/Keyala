Keyala is an experiment in answering one question: when an AI app needs a model API key, who should provide it? Our answer is the user, without ever handing the key to the app. Today the project has a proper home.

## What's new

- **Developer docs** at [keyala.io/docs](https://keyala.io/docs/): one page from the first call to the usage dashboard, with the full API list. The same text is a single Markdown file you can download or give to an AI coding assistant.
- **User guide** at [keyala.io/guide](https://keyala.io/guide/) in English, 繁體中文 and 日本語: signing in, adding a key, connecting an app, approving calls, limits and OpenRouter.
- **Web console** at [app.keyala.io/console](https://app.keyala.io/console): your keys (last four characters only), connected apps you can revoke, and your request history. Developers can create apps and read each app's report there.

## Signing in on the web

Scan the QR code on the console with the Keyala app and tap **Approve web sign-in**, or use your account email with a web password you set in the app under **Settings > Web password**. A web sign-in lasts 12 hours.

> Only approve a web sign-in that you started yourself, on your own computer. Never approve a code someone else sent you.

The web console can look, but it cannot approve calls, add or change keys, or widen what an app is allowed to do. Those stay on your phone.

## Still a beta

Keyala is an experimental personal project and free during the beta. The iPhone app is in invite-only TestFlight; write to [support@keyala.io](mailto:support@keyala.io) to join.
