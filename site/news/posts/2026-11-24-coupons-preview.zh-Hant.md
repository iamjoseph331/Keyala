目前透過 Keyala 使用 App，必須先連接自己的 API key。對只是想看看 App 好不好用的人來說，門檻有點高。所以我們設計了 **Coupon**，預計在下一個版本登場。

## 一句話說明

開發者為自己的 App 贊助幾次試用；你在 Keyala 領券，不必新增 API key 就能試用。

![開發者直接付費給供應商，Keyala 保管 key 與上限，你只能用在該 App](../../../media/news/coupon-flow.zh-Hant.svg)

- **開發者直接付費給模型供應商。** 用量記在開發者自己的供應商帳號。Keyala 不販售 Coupon，也不經手任何金錢。
- **Keyala 保管開發者的 key 並執行上限。** key 和你的 key 一樣加密保存在伺服器上。你看不到它，也無法拿到其他 App 使用。
- **你安裝 Keyala 並領券。** 不需要 API key。Coupon 只能用在發行它的 App。

## 好懂的額度規則

開發者發行一批 Coupon 時，會設定要分享幾張、每張額度多少，以及整批的總預算。預算在**你領券時**才保留，而不是在發出邀請時。所以就算有人分享了券卻沒人領，也不會浪費預算。

![30 張 US$1 的 Coupon、整批預算 US$20：前 20 位領券者各保留 US$1，之後的人會看到領取上限訊息](../../../media/news/coupon-limits.zh-Hant.svg)

以上圖為例：30 張、每張 US$1、整批預算 US$20。前 20 位領券的人，每人都有完整的 US$1 可用。第 21 位會看到「此 Coupon 已到領取上限」，而不是試用到一半就被中斷。

每張領到的 Coupon 也遵守幾條簡單的規則：

- **有效期限。** 預設 7 天，發行者可以自訂長度。
- **預設不顯示 App 的提示詞。** 有些開發者不希望試用者看到自己寫的提示詞，因此由開發者決定是否顯示，預設關閉。你仍然看得到費用和 Coupon 剩餘的額度。
- **用完就停止。** 你的 Coupon 或整批額度用完時，請求會停止並顯示明確的原因。Keyala 絕不會在未經你同意的情況下改用你自己的 key。

## 還在討論的部分

細節仍在決定中：多個請求同時進行時如何避免超支、一人領多張等濫用、Coupon 到期後未用完的預算如何處理，以及開發者在 Coupon 報表中看得到什麼。這些會在 Coupon 上線前定案，開發者文件也會寫明最終的行為。
